# 绿联阵列转换（ugacltool）

把绿联已有的 Btrfs 阵列接入飞牛，保留原硬盘和原文件，不重建 RAID、不格式化，也不迁移数据。接管完成后，阵列出现在飞牛自己的存储空间中，文件访问和共享都通过飞牛管理。

**先看这三个入口：**

- **[最新版安装包 · GitHub Releases](https://github.com/appdev/ugacltool/releases)**：在最新提供安装包的发布中下载 `ugacltool.fpk`。当前为 **v0.2.1 开发预览版**；`SHA256SUMS` 用于核对下载文件。
- **[安装与使用说明](#从安装到接管)**：从飞牛应用中心安装、选择绿联阵列，到完成接管后的文件入口。
- **[支持的飞牛版本与阵列范围](#支持的飞牛版本与阵列范围)**：安装前先核对系统、内核和阵列状态。

## 支持的飞牛版本与阵列范围

| 项目 | 当前支持范围 |
| --- | --- |
| 飞牛系统 | fnOS **1.2.0701** |
| 内核 | **6.18.18.c1107-trim** |
| 设备平台 | x86，与安装包清单一致 |
| 阵列结构 | 完整健康的 MD → 单个线性 LVM LV → 单设备 CRC32C Btrfs |
| 隔离环境完整验证样本 | 单盘 linear / JBOD、单成员 RAID1 / Basic、四成员 RAID6 |

工具还会检查关键存储组件的哈希，版本或组件不匹配会停止。上表中的阵列是已验证样本，不能据此推断所有绿联机型、阵列布局或其他飞牛版本都适用。

## 从安装到接管

1. 下载 `ugacltool.fpk`，在飞牛应用中心手动安装，用管理员账号打开“绿联阵列转换”。
2. 选择需要接管的阵列，按实物核对成员硬盘的序列号、型号和容量。只读核验通过后，接管按钮才会启用。
3. 点击“接管为飞牛存储空间”。后台先在独立写入副本中验证，再完成原阵列的兼容转换、原生登记、开机维护和读写检查。
4. 成功后进入飞牛存储管理和文件管理。旧文件位于当前账号的 `UGREEN` 文件夹，共享通过飞牛自己的设置完成。

接管后的日常使用不需要手动挂载硬盘、运行命令或进入研发阶段的临时目录。系统分区需至少留出 **3 GiB** 可用空间，每组任务会保留 **2 GiB** 隔离验证文件和恢复记录。

转换期间不要关机、升级系统、拔盘或卸载应用。任务停止后保留原记录，通过页面的“继续核验”检查同一组硬盘和同一版代码；隔离验证或备份不完整时需人工排查，不能强制跳过。

请先确认备份可用。“无损”指保留阵列和原文件，正式接管仍会写入兼容标记、修改 LVM 名称、登记飞牛存储信息并创建个人目录。它不是厂商提供的通用导入功能，扩容、修复和快照管理尚未认证。

## 代码结构

```text
scripts/   接管页面服务、阵列发现、任务编排及原有转换与保护模块
web/       飞牛应用内的管理员页面，无外部脚本或 CDN
packaging/ 飞牛原生应用清单与生命周期入口
tools/     安装包构建、公开附件打包、配置检查与持久 COW 验证
tests/     合成文件、模拟设备拓扑、故障和拒绝路径测试
examples/  不含真实硬盘身份的三组阵列配置模板
MANIFEST.json  附件文件 SHA256 清单
```

发布采用明确的源码白名单，不包含研究文档、真实硬盘身份、账号密码、运行记录、厂商二进制或 ISO。[配置模板](examples/storage.json.example)中的身份均为占位符，原样使用会被拒绝。应用升级通过飞牛应用中心完成，不要直接覆盖运行中的代码或使用其他版本的任务记录。

## 必须保留的保护

一键页面只读发现阵列，自动追踪当前根目录、启动分区、独立 home 和原生空间 1 的物理盘。选择时冻结成员盘的序列号、型号、精确整盘字节容量和 MD 身份，每次执行前再次校验；其他物理盘进入保护清单。系统盘、已被飞牛接管的阵列、重复序列号、缺盘、型号或容量变化均拒绝。开发者仍可使用显式策略模板；其中真实硬盘身份全部改为参数。

原有 MD/LV/Btrfs UUID、健康与占用检查、原生空间编号保护、版本固定、持久日志和备份也保留。策略冻结在新的 v2 转换/接管日志中；原卷 COW 证据还需匹配同一硬盘策略。没有强制继续或关闭保护的选项。

## 环境与测试

Python 3.9+；安装包使用飞牛现有的 Python、MD/LVM/Btrfs/systemd 工具，无 Python 第三方依赖。一键流程不依赖 bindfs 或 QEMU。研发附带的 SSD overlay 工具另外需要 `qemu-img`。

以下命令只运行合成文件与 mock 设备测试，不应使用 sudo，不执行真实阵列转换、挂载或格式化：

```sh
python3 -m unittest discover -s tests -v
```

在非 Linux 上，实际 `renameat2` 文件夹发布测试会跳过。单元测试不代表真实硬盘已经完成转换。

构建源码附件：

```sh
python3 tools/build_release.py --output /path/to/new-source.zip
```

使用飞牛官方 `fnpack` 构建安装包，输出目录必须尚不存在：

```sh
python3 tools/build_fpk.py --fnpack /path/to/fnpack --output /path/to/new-build-directory
```

## 不适用的情况

当前工具仅支持完整健康的 MD → 单个线性 LVM LV → 单设备 CRC32C Btrfs，拒绝未知特性、额外映射、额外 LV、降级、活动重建和待重放日志。策略还限制一块物理盘仅归属一组目标阵列；无法唯一读取序列号或无法追踪系统盘时停止。

不保留 UGOS 的 ACL/配额语义，不认证返回 UGOS、原生扩容/修复/快照管理、多账号 ACL、断电恢复、系统升级或性能完全等价。正式 RW 后不能恢复旧超级块当作回退。“无损接管”的范围是保留原文件并接入原生存储、账号读写和共享，不代表全部飞牛存储管理功能已兼容。

隔离验证需要系统分区至少 3 GiB 可用空间，并为每组阵列保留 2 GiB 验证文件和私有恢复记录。应用卸载不清理这些记录，也不停止已接管空间的独立启动服务。中断任务可以按原记录核验继续；COW 或原生备份尚未完整生成时，需要人工检查，不能强制跳过。

本附件没有代替发布者选择开源许可证，也未附厂商组件的再分发授权；发布时保留代码来源说明，按自己的发布方式补充许可文件。
